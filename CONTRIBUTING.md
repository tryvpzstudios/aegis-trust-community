# Contributing to AEGIS TRUST

Thank you for your interest.

## Workflow
1. Read README.md, TASKS.md and SECURITY.md.
2. Open an issue describing the task, approach, expected output and risks.
3. Wait for maintainer acceptance before substantial work.
4. Work only with public materials, synthetic data and your own code.
5. Submit a pull request with tests, evidence, limitations and summary.
6. Respond to review. Maintainers may request changes or decline work.

## Standards
- Small, focused, reproducible contributions.
- Report tests and validation honestly.
- Document uncertainty, false positives/negatives, limitations and data provenance.
- Use accessible, mobile-friendly and privacy-preserving designs.
- Never include secrets, credentials, personal data, private evidence or restricted material.

## IP, compensation and access
This public repository does not promise employment, salary, equity, prizes, revenue share or future compensation. Before any paid, commercial, confidential, patent-sensitive or specially scoped work begins, parties must agree in writing on scope, compensation (if any), attribution, IP ownership/license, confidentiality and permitted use. Do not begin such work without that agreement.

Submitting a pull request does not grant access to private repositories or systems. Maintainers decide whether contributions are accepted. Do not assume a contribution is accepted, commercially used or production-deployed until explicitly confirmed.

## Pull request checklist
- [ ] Scope linked to an issue or approved task
- [ ] No secrets/private data/confidential material
- [ ] Tests/validation and results stated
- [ ] Limitations and risks documented
- [ ] Dependencies and licenses identified
- [ ] Documentation updated where needed
